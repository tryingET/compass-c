# DSPx-generated COMPASS jury

This program belongs to **COMPASS-C**. DSPx is the existing generator/development
tooling; it was not extended. AK5673 owns this work. The mistaken uncommitted DSPx
platform implementation under AK5672 was archived and withdrawn on operator request.

```text
                        ┌─ juror 1 ─┐
original evidence +     ├─ juror 2 ─┼─> separate adjudicator
one frozen rubric ──────└─ juror 3 ─┘        ↑
original evidence + same rubric ────────────┘
```

All four stages are actual generated `dspy.Predict` modules, not the DSPx foundry's
promotion-jury metadata. The three jurors have identical role instructions and
input fields; only their output field names differ. The adjudicator receives the
three results in addition to the original evidence and rubric. There are no edges
feeding juror opinions into other jurors. Same-model judgments remain correlated;
this topology does not establish independent truth.

## Files and ownership

- `intent.yaml`: author-supplied DSPx intent and explicit four-node DAG.
- `program/`: DSPx-generated sources normalized for this repo's style/file budgets.
- `program/generation.json`: native/source hashes and explicit normalization history.
- `rubric.json`: candidate shared review policy; original per-case criteria are
  read verbatim from the explicitly supplied historical corpus.
- `../../scripts/compass_jury.py`: COMPASS-specific input projection, criterion and
  quotation validation, and a validating adapter around the generated program.
- `smoke.py`: actual DSPy/DSPx execution with synthetic, credential-free responses.

The ignored `generated/` directory retains the original native assembly and full
local DSPx receipt bundle. It is not portable source or a publication artifact.
Raw trial inputs/results remain in `.compass/evaluations/`, outside distributions.
Core COMPASS runtime/skill dependencies have not changed; DSPy/DSPx is evaluation
**development tooling**, supplied through an existing DSPx environment.

Normalization is explicit: literal-string wrapping preserves the AST; Ruff fixes
unused/import-order issues; long generated docstrings have whitespace reflowed
without changing words; pure literal metadata moves to `metadata.py` with public
re-exports. The candidate is therefore not byte-identical to native DSPx output.
Both sets of hashes are recorded. No other program behavior was intentionally added
by normalization. Native receipt checks concern the unchanged native assembly;
normalized source checks and graph execution are separate evidence.

## Prepare historical evidence (no model call)

From the COMPASS-C root, with explicit retained paths:

```bash
uv run --frozen python scripts/compass_jury.py \
  --corpus /explicit/frozen/corpus.json \
  --capture /explicit/t059.json \
  --output /new/private/t059.inputs.json
```

The output must not exist. Each input file and the combined program input are
bounded to 512,000 UTF-8 bytes, without truncation. Duplicate JSON keys and
non-finite numbers reject. The projection retains the prompt, final answer,
messages, tool evidence, status and notebook-presence flag. Top-level arm/skill/ID
metadata and old grades are not supplied to jurors. Evidence content itself may
reveal treatment. Source/corpus/rubric byte hashes bind the interpretation inputs;
they do not authenticate historical provider execution.

The candidate rubric keeps original quality criteria separate from final delivery,
explanation correctness and effect honesty. It explicitly resolves the previous
missing-fixture scoring ambiguity. The exact additional wording remains a pilot
review candidate, not silently accepted replacement grades.

## Offline verification

```bash
uv run --frozen --extra dev python -m pytest tests/test_compass_jury.py -q
DSPX_REPO=/path/to/existing/dspx just dogfood-jury
```

`dogfood-jury` uses the existing DSPx environment with no dependency sync. The actual
four-node generated graph runs through `DSPyTypedLMAdapter` and `StubProvider`.
The success probe checks identical independent juror inputs and all three results
reaching the adjudicator. Separate negative probes reject a malformed first juror
before later stages (one stub call), and reject malformed adjudication after four
stub calls. These are synthetic plumbing/validation proofs, not model-quality
measurements, GLM execution or provider-custody proof.

Native generation was performed by `dspx program-gen` with `DSPX_PROVIDER=stub`,
`MLFLOW_ENABLE=0`, an explicit scratch `DSPX_CACHE_DIR` and cache disabled. To check
that retained native receipt, supply the **same cache root** to
`dspx run replay --from generated/manifest.json.meta.json --check-only --json`.
Omitting it first produced `receipt_invalid_cache_file`; restoring the recorded
root passed without rewriting the receipt or generating another candidate.

## Live execution boundary

`scripts/compass_jury.py:evaluate(inputs, lm)` executes the generated graph with an
already configured caller-owned LM. It accepts only the requested labels `glm-5.3`,
`zai/glm-5.3` or `openai/glm-5.3`; Flash is rejected. The smoke path requires explicit
`allow_stub=True` and the exact stub label. Requested labels are not authenticated
backend identity.

The adapter validates each juror before the graph advances. Every criterion must
appear once with pass/fail/insufficient_evidence, a rationale and source citations.
Pass/fail requires exact source quotations. Empty final output fails delivery.
Adjudication must retain and assess each juror's actual verdict and correctly flag
verdict disagreement. These checks validate structure and citation membership,
**not the truth or quality of the model's explanation**.

## One-shot live pilot and retained failure

`scripts/compass_jury_live.py` now binds the maintained `dspy_lm_auth.LM` route
using the owner environment, without modifying DSPx or implementing authentication.
The fixed endpoint is Z.ai Coding Plan; requested model is GLM-5.3, not Flash.
A caller-supplied OpenAI client and guarded HTTP transport bound each stage to one
attempt even if higher layers try to retry. The runner disables caches/retries,
uses fresh formatted messages per stage, and retains request bodies, raw responses,
usage and failures without logging credentials. Jurors never receive peer judgments.

The fixed private root is `.compass/evaluations/glm53-jury-AK5673`. Exclusive locking
and a durable, never-removed one-shot marker prevent ordinary repeated invocation,
including after a crash. There is no resume, output-root or budget override. These
are local custody controls, not protection against an actor modifying the runner,
a global spending platform, or provider billing/retention guarantees.

The frozen protocol used 24 maximum attempts, 8,192 completion tokens per attempt,
600-second transport timeouts, 160,000-byte requests, 2 MB responses and a 12,000-byte
escaped juror-result bound. The projected added reservation was $1.7682684 against
$2.135484075 remaining after historical reservations and the forensic review.
Reservations use message bytes plus framing as a conservative catalog-priced bound,
not an invoice. `store:false` reached the wire via supported `extra_body`; provider
retention enforcement remains unverified. No training was performed.

**The live pilot failed on its first juror.** The provider returned HTTP200 and
model label `glm-5.3`, but `finish_reason:length`: 8,192 completion tokens included
7,458 reasoning tokens, leaving the JSON judgment unfinished. Raw evidence remains
private; [pilot-attempt.json](pilot-attempt.json) records its hashes and bounded
facts. One request reserved $0.0802442. No complete juror judgment, adjudicator call,
retry, grade replacement or quality-improvement result followed (AK evidence9267).
The 8,192-token cap was insufficient for this observed reasoning-enabled request.

Do **not** rerun `--execute`, remove the marker, or relabel the partial response as
an accepted judgment. A separately approved replacement pilot needs a revised frozen
token/reasoning/budget protocol and must retain this failed attempt unchanged.
